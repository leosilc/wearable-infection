# NightSignal under Missing Data

A fork of [StanfordBioinformatics/wearable-infection](https://github.com/StanfordBioinformatics/wearable-infection) that studies how the **NightSignal** infection-detection algorithm behaves when overnight heart-rate data is partially missing. Part of an undergraduate research project (*Iniciação Científica*).

NightSignal raises a daily alert (green / yellow / red) from overnight resting heart rate. This fork injects controlled missingness into the input under three mechanisms — **MCAR**, **MAR** and **MNAR** — re-runs the algorithm, and compares the resulting alerts against the complete-data run.

> Based on: Alavi et al., *Real-time alerting system for COVID-19 and other stress events using wearable data*, **Nature Medicine** 28, 175–184 (2022). https://doi.org/10.1038/s41591-021-01593-2

---

## Requirements

Python 3.10+. Install dependencies with:

```bash
pip install -r requirements.txt
```

---

## Data

The `data/` folder is not committed. Provide raw Fitbit exports per patient:

```
data/raw/{patient_id}/
├── Orig_Fitbit_HR.csv     (datetime, heartrate)
└── Orig_Fitbit_ST.csv     (datetime, steps)
```

The remaining `data/` subfolders (`processing/`, `missing/`) are generated by the pipeline.

---

## Usage

Run the scripts in order:

```bash
python3 run_all.py                # preprocess + run NightSignal on complete data (baseline)
python3 generate_missing.py       # inject MCAR/MAR/MNAR at several rates + re-run NightSignal
python3 overall_results.py        # confusion matrices and metrics vs. baseline + heatmaps
python3 plot_patient_boxplots.py  # boxplots of the metrics across patients
```

Missing rates and MCAR seeds are configured at the top of `generate_missing.py`.
Use `python3 clean.py` to reset the generated folders.

Results (signals, plots, metrics) are written under `results/`.
